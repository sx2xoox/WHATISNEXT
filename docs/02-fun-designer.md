# 탈출 설계사 (가제) — 재미 설계자

> 1인 개발 기준으로 추정했습니다. 수치는 모두 초안이며 프로토타입 결과로 수정합니다.

## 1. 한 줄 소개

방탈출 카페 사장이 되어 방을 설계하고, AI 손님들이 **아슬아슬하게** 탈출할수록 높은 평점을 받는 설계 시뮬레이션.

## 2. 핵심 판타지

- 내가 게임 디자이너가 되어, 남이 내 작품을 즐기는 모습을 지켜본다.
- 손님이 마지막 10초에 문을 열고 환호하는 순간이 최고의 보상이다.
- 감정 흐름: 설계하는 몰입 → 지켜보는 긴장 → 평점을 받는 뿌듯함 (또는 혹평에 대한 오기)

## 3. 핵심 루프

| 단위 | 내용 |
|---|---|
| 30초 | 퍼즐과 장치를 배치하고, 힌트 위치를 조정함 |
| 1회차 (하루 영업) | 손님 그룹 입장 → 관찰 (배속 가능) → 리뷰와 평점 확인 → 방 수정 |
| 메타 (여러 회차) | 매출로 새 테마와 장치를 해금 → 가게 확장 → 손님층 다양화 (초보 커플, 마니아, 아이 동반 가족) |

## 4. 주요 메커닉

- **손님 성향**: 관찰력, 인내심, 협동심, 공포 내성. 그룹마다 조합이 다르다.
- **긴장 곡선**: 손님의 감정이 실시간 그래프로 표시된다. 플레이어가 "왜 이 평점이 나왔는지" 이해하게 만드는 핵심 장치다.
- **점수 규칙**:
  - 제한 시간의 85~100%를 써서 탈출 → 최고 평점
  - 너무 빨리 탈출 → "지루했다" 리뷰
  - 탈출 실패 → 분노 리뷰
- **퍼즐 의존 구조**: 자물쇠와 열쇠의 연결 관계로 방을 구성한다. 막다른 길이나 순서 오류가 생기면 경고한다.
- **무전 힌트**: 영업 중 직접 힌트를 보내 개입할 수 있다. 대신 평점이 조금 깎인다.
- **의뢰**: "공포 테마인데 아이도 즐길 수 있게"처럼 조건이 붙은 의뢰로 최적해 고착을 막는다.

## 5. 차별점과 유사 게임

| 유사 게임 | 공통점 | 차이점 |
|---|---|---|
| Two Point Hospital, Theme Park | 경영과 손님 관찰 | 시설 운영이 아니라 **경험 설계** |
| Dungeon Keeper, Legend of Keepers | 공간 설계, 침입자 AI | 막는 게 목표가 아니라 **적당히 어렵게** 하는 게 목표 |
| Mario Maker | 레벨 제작 | AI가 플레이하고 평가함 |
| Escape Simulator | 방탈출 소재 | 푸는 쪽이 아니라 **만드는 쪽** |

**차별점 한 문장**: 이기는 게 아니라 손님을 즐겁게 하는 게임. 몰입 이론(플로우)을 게임으로 만든 셈이다.

## 6. 타깃과 플랫폼

- **타깃**: 경영·샌드박스 게임을 즐기는 PC 유저, 방탈출 팬, 게임 제작에 관심 있는 사람
- **플랫폼**: PC(Steam) 우선

## 7. 수익 모델

- 유료 판매 $14.99~19.99
- 출시 후 테마 DLC
- 유저가 만든 방 공유 (Steam 창작마당)로 수명 연장

## 8. 아트·사운드 방향과 제작 범위

- **아트**: 2D 탑다운 단면 뷰. 손님 머리 위에 감정 아이콘을 띄운다. 장치 아이콘은 PixelLab으로 다량 생성한다.
- **사운드**: 손님의 탄성, 한숨, 비명 같은 반응음이 피드백의 중심이다.
- **출시 범위**: 장치 30종, 테마 4개, 손님 유형 6종, 의뢰 40개

## 9. MVP에서 검증할 질문

1. 손님 행동을 **지켜보는 것 자체**가 재미있는가?
2. 플레이어가 평점이 나온 **이유를 이해**하는가?
3. 수정하고 다시 돌려보는 루프에서 "한 번만 더"가 생기는가?

**MVP 범위**: 방 1개, 장치 6종, 손님 유형 2종, 긴장 곡선 표시, 평점 계산

## 10. 일정 (1인 기준 추정)

| 단계 | 기간 |
|---|---|
| 프로토타입 | 3~4주 (손님 AI 때문에 셋 중 가장 김) |
| 버티컬 슬라이스 (테마 1개 완성) | 4개월 |
| Steam 데모 | 6~7개월 |
| 정식 출시 | 14~18개월 |

## 11. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 손님 AI가 그럴듯하지 않음 | 복잡한 AI 대신 단순한 확률 모델에 **풍부한 반응 표현**을 입힘 |
| 관찰 시간이 지루함 | 배속, 하이라이트만 모은 요약 리플레이 |
| 최적의 방 하나로 고착됨 | 손님 다양성, 조건부 의뢰, 테마 제약 |
| 설계 에디터 개발 비용이 큼 | 격자 기반 배치로 단순화 |

## 12. 중단 기준

- 테스터가 평점의 이유를 설명하지 못하면 피드백 표현을 다시 설계한다.
- 그래도 "보는 게 지루하다"는 반응이면 접는다.
